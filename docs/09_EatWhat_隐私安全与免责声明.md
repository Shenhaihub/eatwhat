# 2. 合规定位

## 2.1 当前项目定位

EatWhat 当前是：

- 个人 GitHub 全栈作品；
- 小规模在线演示；
- 不以商业化为当前目标；
- 不开展支付、广告和商家交易；
- 不主动建立长期用户画像；
- 不提供医疗和营养服务。

## 2.2 不能因为是作品项目而忽视隐私

只要在线处理真实用户的：

- 邮箱；
- 登录信息；
- 位置；
- 问卷答案；
- 推荐历史；
- 反馈；

就需要按个人信息保护原则进行设计。

## 2.3 法律边界说明

本文件只提供产品与工程层面的合规设计。

未来若发生以下变化，应重新进行专业法律审查：

- 正式商业运营；
- 大规模用户；
- 广告或付费；
- 儿童用户；
- 长期用户画像；
- 海外模型或跨境数据；
- 与商家合作；
- 算法备案或生成式 AI 备案相关场景；
- 收集手机号、身份证或支付信息；
- 处理医疗健康信息。

# 3. 数据处理原则

EatWhat v1.0 遵循以下原则：

## 3.1 目的明确

只处理完成相应功能所需的数据。

## 3.2 最少够用

能不收集就不收集，能短时使用就不长期保存。

## 3.3 用户知情

在收集前说明：

- 收集什么；
- 为什么收集；
- 用于什么；
- 是否保存；
- 如何拒绝。

## 3.4 用户自愿

匿名共享、位置权限和反馈均可拒绝。

拒绝后不能阻止用户使用与其无关的基本功能。

## 3.5 权限隔离

用户只能访问自己的：

- 推荐历史；
- 问卷答案；
- 反馈；
- 额度。

## 3.6 安全保护

使用：

- HTTPS；
- Token 验证；
- 最小权限；
- 输入校验；
- 日志脱敏；
- 数据库约束；
- 依赖更新；
- Secret 管理。

# 6. 位置数据设计

## 6.1 为什么谨慎处理

位置能够反映用户活动范围。

EatWhat 采取比最低功能要求更严格的工程策略：

> 将精确经纬度按高敏感度数据处理。

## 6.2 权限申请时机

不能在用户刚进入首页时立即申请。

只有用户点击：

- 查看附近商家；
- 活动附近门店；
- 公共食物附近商家；

才申请位置。

## 6.3 权限前说明

推荐文案：

> 为了查找你附近的餐饮商家，EatWhat 需要获取一次当前位置。位置仅用于本次附近搜索，默认不会保存精确经纬度。你也可以选择手动搜索地点或使用演示地点。

按钮：

```text
[使用当前位置]
[手动选择地点]
[暂不使用]
```

## 6.4 拒绝定位

拒绝后：

- 不反复弹窗；
- 提供手动搜索；
- 提供演示地点；
- 允许只查看食物类型。

## 6.5 服务端处理

```text
浏览器获得坐标
→ HTTPS发送给FastAPI
→ FastAPI调用POI Provider
→ 返回商家
→ 请求结束后不写入历史
```

## 6.6 日志

禁止记录：

```text
latitude=30.123456
longitude=114.123456
```

日志可记录：

```text
location_source=browser
city_code=420100
```

## 6.7 位置 Token

可以把精确位置短时保存在：

- 内存缓存；
- 加密或签名的短时 Token；
- 有明确过期时间的缓存对象。

建议有效期：

```text
当前会话或短时间
```

不作为长期个人位置档案。

# 7. 问卷与忌口信息

## 7.1 “一般忌口”定位

问卷只问：

> 今天有哪些不想吃的东西？

不问：

- 是否患病；
- 是否有具体过敏诊断；
- 药物；
- 医疗历史。

## 7.2 免责声明

忌口题下方提供：

> 本功能仅用于日常饮食选择，不构成医疗、营养或过敏安全建议。存在食物过敏或疾病饮食限制时，请自行向商家确认配料、加工方式和交叉污染风险。

## 7.3 输入形式

使用系统选项代码，不使用自由文本描述病情。

## 7.4 AI 使用

发送给 AI 的内容只包含：

```text
avoidances = ["seafood", "greasy"]
```

不发送：

- 用户身份；
- “我患有什么疾病”；
- 医疗记录；
- 完整自由文本。

# 8. Supabase Auth 安全边界

## 8.1 EatWhat 不保存密码

密码交由 Supabase Auth 处理。

业务数据库只保存：

```text
user_id
```

## 8.2 Token

前端使用官方客户端管理会话。

不得：

- 手工把 Token 输出到控制台；
- 在错误监控中上传 Token；
- 在 URL 中传 Token；
- 把 Token 写入 GitHub。

## 8.3 后端验证

FastAPI 每次验证：

- 签名；
- 过期；
- issuer；
- audience；
- 必需字段。

## 8.4 Secret Key

Supabase Secret/Service Role 凭据：

- 只放服务端；
- 只使用必要权限；
- 不进入前端环境变量；
- 不使用 `VITE_` 前缀暴露；
- 泄露后立即轮换。

# 9. AI 服务隐私

## 9.1 最小输入

AI 只接收：

- 用餐时段；
- 胃口代码；
- 一般忌口代码；
- 口味代码；
- 预算；
- 合法候选食物；
- 补问答案。

## 9.2 不发送

- 邮箱；
- user_id；
- 经纬度；
- 地点名称；
- 具体商家；
- Token；
- 个人历史全文；
- 反馈自由文本。

## 9.3 模型提供商选择

中国大陆公开部署时，优先选择：

- 能明确说明数据处理方式的 Provider；
- 可关闭训练用途或提供企业数据控制的服务；
- 符合目标地区可用性和合规要求的模型；
- 已完成适用备案或登记要求的模型服务。

## 9.4 跨境风险

若调用境外模型 API，即使不发送姓名，也应评估：

- 输入是否仍可关联到个人；
- 是否构成个人信息跨境提供；
- Provider 的存储区域；
- 日志保留；
- 合同和隐私条款；
- 是否需要单独同意或其他合规措施。

v1.0 中国大陆公开演示优先使用：

```text
国内可用 Provider
或
彻底去身份化后的最小结构化输入
```

这不是对跨境合规的最终法律结论。

# 12. 匿名共享

## 12.1 必须主动选择

推荐完成后默认：

```text
未共享
```

不能预先勾选“同意共享”。

## 12.2 共享前摘要

页面必须说明。

会共享：

- 星期；
- 用餐时段；
- 粗略城市和区域；
- 结构化问卷选项；
- 最终食物类型；
- 来源；
- 满意度。

不会共享：

- 邮箱；
- 精确经纬度；
- 详细地址；
- 具体商家；
- 完整 AI 对话；
- 密码或 Token。

## 12.3 推荐确认文案

> 是否愿意匿名分享本次选择，帮助其他人决定今天吃什么？共享内容不包含邮箱、精确位置、具体门店或完整 AI 对话。

按钮：

```text
[不用了]
[查看共享内容]
[匿名分享]
```

## 12.4 后端生成共享数据

前端只提交：

```json
{
  "confirmed": true
}
```

后端从推荐记录提取允许字段。

避免前端提交额外敏感数据。

## 12.5 阈值保护

同一种食物至少 3 条共享记录才显示人数。

防止过小样本暴露个体选择。

## 12.6 注销后的共享

v1.1 注销时：

```text
source_user_id = NULL
source_session_id = NULL
```

保留完全无法再关联原账户的聚合数据。

如果无法达到合理匿名化，应删除。

# 19. 前端安全

## 19.1 XSS

由于浏览器持有登录会话，必须重点防止 XSS：

- React 默认文本转义；
- 不随意使用 `dangerouslySetInnerHTML`；
- 用户反馈按纯文本显示；
- 配置内容进行校验；
- 使用 Content Security Policy；
- 依赖定期更新。

## 19.2 Token

- 使用 Supabase 官方客户端；
- 不打印会话；
- 不在 URL 中传；
- 不发给 AI 或高德；
- 退出登录后清理会话和位置缓存。

## 19.3 第三方链接

地图跳转：

- 只允许高德等明确域名；
- 不直接相信第三方返回的任意 URL；
- 必要时由后端构造安全跳转链接。

## 19.4 敏感输入自动完成

# 26. 威胁模型

| 威胁 | 防护 |
|---|---|
| 修改前端额度 | 后端数据库校验 |
| 多请求绕过3次 | reserved_count + 事务 |
| 网络重试重复扣 | idempotency_key |
| 伪造 user_id | 只信验证后的 Token sub |
| 查看他人历史 | 所属关系检查 |
| XSS窃取会话 | 转义、CSP、避免危险HTML |
| Key泄露 | 后端调用、Secret管理 |
| 精确位置泄露 | 不持久化、不记录 |
| Prompt注入 | 枚举输入、Schema、候选白名单 |
| AI编造商家 | AI不接收商家任务 |
| 公共小样本暴露 | 至少3条才显示人数 |
| 恶意刷短信 | v1.0不使用手机号验证码 |
| 演示账户污染 | 定期清理和公共提示 |

# 34. 安全验收标准

## 34.1 认证

- 无 Token 无法读取个人数据；
- 错误 Token 被拒绝；
- 用户不能读取他人历史；
- 退出后会话失效。

## 34.2 Secret

- 前端构建产物中没有 Secret；
- Git 历史中没有 Secret；
- 生产 Secret 可轮换。

## 34.3 位置

- 精确坐标不写业务表；
- 普通日志无精确坐标；
- 拒绝定位仍可继续；
- 会话结束可清除位置缓存。

## 34.4 AI

- AI 输入无身份和位置；
- AI 输出有标识；
- 非法输出被后端拦截；
- 失败后安全降级。

## 34.5 公共数据

- 小于3条不显示人数；
- 接口不返回单条用户记录；
- 默认热门项不虚构人数；
- 删除用户后共享数据无法关联原账号。

## 34.6 用户控制

- 可删除单条历史；
- 可清空历史；
- 可拒绝共享；
- 可拒绝反馈；
- v1.1 注销任务被明确记录。
