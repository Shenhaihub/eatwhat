# ADR-002: 社区模块冷启动与匿名统计规则

> 日期：2026-08-24
> 状态：已采纳
> 关联：P6-01 / P6-02

---

## 1. 背景

EatWhat 的社区模块（`/api/v1/community`）需要展示：
- **"大家今天吃什么" Feed 流**：展示用户分享的餐食动态
- **今日推荐 Top 榜**：展示当天被推荐最多的食物
- **本周主题投票**：引导社区互动

当前这些功能全部使用 Mock 数据，需要接入真实数据。但在 MVP 阶段，真实用户量有限，直接展示少量真实数据会导致页面冷清、缺乏可信度。

本 ADR 定义社区模块的冷启动策略和匿名统计规则。

---

## 2. 决策

### 2.1 冷启动策略

**阶段划分**：

| 阶段 | 用户量 | 策略 | 数据来源 |
|------|--------|------|----------|
| **Seed 阶段** | < 100 DAU | 展示高质量 Seed 内容 | 预配置内容 + Mock 聚合 |
| **过渡阶段** | 100-1000 DAU | 混合展示（真实 + Seed） | 真实历史记录 + Seed 内容 |
| **成长阶段** | > 1000 DAU | 纯真实数据 | 真实历史记录聚合 |

**MVP 阶段（Seed 阶段）的具体做法**：

1. **Feed 流**：
   - 展示 10 条预配置的 Seed 内容（`_MOCK_FEED_SEED`）
   - 允许用户点赞、投票（写入内存）
   - 不允许用户发布动态（MVP 阶段）

2. **Trending 榜**：
   - 展示 5 条预配置的 Mock 聚合（`_TRENDING_SEED`）
   - 标记为"模拟数据"或"示例数据"
   - 后端预留聚合接口，接真实数据时切换

3. **Theme 投票**：
   - 展示预配置的主题（日料 vs 韩餐）
   - 预置一些假票，展示上不至于 0/0
   - 真实用户投票会累加

### 2.2 匿名统计规则

**核心原则**：匿名可读，写操作需登录。

| 操作 | 是否需要登录 | 说明 |
|------|--------------|------|
| 查看 Feed 流 | ❌ | 支持匿名浏览 |
| 查看 Trending 榜 | ❌ | 支持匿名浏览 |
| 查看 Theme 投票 | ❌ | 支持匿名浏览 |
| 点赞 | ✅ | 需登录，幂等 |
| 投票 | ✅ | 需登录，幂等，不可改票 |

**匿名用户行为记录**：
- 不记录可识别个人的信息
- 仅记录聚合统计（如页面浏览量）
- 使用匿名 session ID（Cookie-based）

### 2.3 真实数据聚合（Trending 榜）

**数据来源**：`history` 表的 `food_code` 字段

**聚合逻辑**：
```sql
-- 今日推荐 Top 榜（按 food_code 聚合）
SELECT 
    food_code,
    COUNT(*) as recommended_today
FROM history
WHERE created_at >= CURRENT_DATE
AND food_code IS NOT NULL
GROUP BY food_code
ORDER BY recommended_today DESC
LIMIT 10;
```

**降级策略**：
1. 若真实数据 ≥ 5 条 → 使用真实数据
2. 若真实数据 < 5 条 → 混合 Seed 数据填充到 5 条
3. 若无真实数据 → 纯 Seed 数据，标记"示例数据"

### 2.4 隐私保护

**用户数据不泄露**：
- Trending 榜只展示 `food_code` 和聚合计数，不展示用户 ID
- Feed 流的 `user_id` 是匿名化的展示 ID（如 `u_001`），不是真实 auth.id
- 点赞/投票的真实用户 ID 仅用于去重，不暴露给前端

**数据最小化**：
- 只采集必要的聚合数据
- 不采集用户的位置信息用于社区展示
- 不采集用户的 AI 追问内容

### 2.5 反作弊策略

**投票反作弊**：
- 同一用户对同一主题只能投一次（幂等）
- 不允许切换选项（MVP 简化策略）
- 同一 IP 多个账号投相同选项不计入（未来增强）

**点赞反作弊**：
- 同一用户对同一 Feed 只能赞一次（幂等）
- 不支持取消点赞（MVP 简化策略）

## 4. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Seed 内容过时 | 用户觉得不真实 | 定期更新 Seed 内容（每月一次） |
| 真实数据量少 | 榜单冷清 | 混合 Seed 数据填充，标记"示例" |
| 隐私泄露 | 用户不信任 | 严格执行数据最小化，定期审计 |
| 刷票刷赞 | 数据失真 | 幂等设计 + 未来增加频率限制 |
