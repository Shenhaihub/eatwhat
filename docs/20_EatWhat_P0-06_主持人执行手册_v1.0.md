## 1. 本手册解决什么

方案已经定义了 T1–T7 任务、指标和通过门槛。本手册把这些内容变成主持人可以"照着读、照着记"的逐场流程，避免临场遗漏：

1. 每个会话前要检查什么；
2. 开场说什么、绝对不说什么；
3. 每名参与者分配哪些任务、用哪个链接；
4. 每个任务怎么读题、重点观察什么、成功条件是什么；
5. 怎么记录、怎么判定严重度；
6. 会话后怎么归档文件。

## 3. 每个会话开始前检查清单

在参与者到场前完成，逐项打勾：

- [ ] 已在本目录启动：`node serve.mjs`，确认输出 `EatWhat prototype: http://127.0.0.1:4173`
- [ ] 已为该参与者打开正确的**参与者链接**（见上表）
- [ ] 参与者链接里带 `mode=participant`，页面**看不到"原型控制台"**（页面右下角不应出现控制台面板）
- [ ] 使用**无痕/隐私窗口**，或刷新后从首页开始；每换一个任务重开对应链接
- [ ] 页面缩放为 **100%**
- [ ] 默认未登录状态
- [ ] 计时工具就绪（手机秒表或独立计时器；计时包含思考与操作，模拟等待单列）

- [ ] 已征得录音/录屏同意（如需要录制），否则不录
- [ ] 参与者编号、日期、设备、输入方式已填到记录文件"基本信息"

## 4. 开场词（逐字照读）

> 这是一个尚未完成的交互原型，我们测试的是产品，不是测试你。请尽量说出你正在想什么。遇到困难时先按自己的理解尝试，我不会立即告诉你该点哪里。

参与者身份信息在开始前口头了解即可（是否常纠结吃什么、是否熟悉本项目），填入记录文件。

### 主持红线（绝对不做）

- 不解释首页三路分流；
- 不告诉参与者按钮名称或位置；
- 不暗示预算一定会过滤商家；
- 不在参与者犹豫时立即教学；
- 不把"最终做完了"记成"无障碍完成"。

### 唯一可干预条件

只有参与者**连续停顿约 20 秒**、**明确表示放弃**，或**走入无法恢复状态**时才可干预。干预时记录：时间、原因、说了什么。

## 5. 逐任务执行卡

每张卡：读题（原文）→ 重点观察 → 成功条件 → 目标时间。

### T1 已有明确想法时直接找商家

读题：

> 你已经决定想吃麻辣烫。请使用这个产品查看附近可能相关的商家，不需要它替你重新决定吃什么。

观察：

- 是否从首页明确食物入口进入；
- 是否误入完整推荐问卷；
- 是否理解可以跳过 AI；
- 是否成功到达商家结果。

成功条件：

- 不进入 AI 推荐即可到达麻辣烫附近商家页；
- 无主持人指路；
- 目标时间不超过 60 秒。

### T2 从"不知道吃什么"完成完整推荐

读题：

> 你现在不知道吃什么，想吃正常一餐，没有需要避开的食物，口味都可以，预算是 20–30 元，也没有预先想到某种食物。请让系统帮你决定，并查看一个你愿意考虑的附近商家。

观察：

- 是否找到推荐入口；
- 是否理解问题会变化；
- 登录出现时是否知道此前答案仍被保留；
- AI 等待时是否重复提交或想退出；
- 是否发现"更多推荐"；
- 是否能从推荐结果继续到商家。

成功条件：

- 完成基础题、自适应题、模拟登录和 AI 追问；
- 到达结果后先看到 1 个候选，并能按需展开到 3/5 个；
- 选择食物后通过演示位置或手动地点到达商家结果；
- 无致命错误或主持人代操作；
- 交互时间目标不超过 5 分钟，模拟等待时间单列。

### T3 返回修改与状态恢复

读题：

> 你刚刚想起今天不想吃海鲜，而且希望把预算改成 20 元以下。请修改此前回答，再继续完成推荐。

观察：

- 是否能找到修改入口；
- 是否发现已有答案仍在；
- 是否理解后续问题可能随早期答案改变；
- 修改后是否能继续，而不是被迫从首页重新开始。

成功条件：

- 正确修改两个答案；
- 已有适用答案保留，不适用答案由系统重新判断；
- 参与者能说出"修改可能改变后续问题或结果"。

### T4 定位拒绝后的替代路径

读题：

> 你已经选好了食物，但不想授权浏览器读取当前位置。请继续查找商家。

观察：

- 是否敢于拒绝定位；
- 拒绝后是否看到手动地点和演示位置；
- 是否误以为拒绝即任务结束。

成功条件：

- 拒绝定位后仍能使用替代入口；
- 已选食物不丢失；
- 无主持人干预。

### T5 预算与商家价格理解

**到达商家结果后提问，不提前提示答案：**

1. "你刚才选择的 20–30 元预算影响了什么？"
2. "这里列出的商家是否保证最终花费在 20–30 元？"
3. "如果要确认实际价格，你会去哪里看？"

通过条件：

- 能说明预算用于帮助选择食物方向；
- 明确回答商家价格不受保证；
- 知道应以门店菜单、点单页或现场价格为准。

**这是阻断性理解项**：任意参与者误以为商家被预算可靠过滤，都必须修订文案并复测。

### T6 异常恢复（按分配场景）

至少为不同参与者分配一种：

- AI 首次失败后重试；
- 商家零结果后扩大范围；
- 商家服务错误后重试或使用演示结果。

成功条件：

- 已答问卷、已选食物不丢失；
- 参与者知道当前失败的是哪一层；
- 不需要从首页重做；
- 错误文案没有暗示虚假的成功或价格信息。

### T7 纯键盘主路径（至少 1 人）

指定参与者从首页开始，**仅使用** `Tab` / `Shift+Tab` / 方向键 / `Space` / `Enter`。鼠标和触控不得使用。任务至少覆盖：首页进入推荐、选择问卷答案、提交、模拟登录、完成一轮 AI、返回修改一次并继续。

通过条件：

- 焦点始终可见；
- 无键盘陷阱；
- 所有必要控件可达并可激活；
- 页面切换后焦点到达当前页主标题或合理位置；
- 错误出现后焦点进入错误摘要；
- 不因浮动元素遮挡当前焦点。

## 6. 记录速查（每个任务）

在记录文件对应任务表里记：

| 指标 | 怎么记 |
|---|---|
| 开始/结束 | 读题结束到达成目标 |
| 总时间 | 含思考与操作 |
| 模拟等待时间 | AI/POI 人为延迟，与交互时间分开 |
| 结果 | 独立完成 / 干预后完成 / 失败 |
| 首次明显卡点 | 页面、控件、当时原话 |
| 误操作 | 点错、重复提交、错误返回、误入分支 |
| 返回修改次数 | 主动返回及原因 |
| 主持干预 | 时间、原因、提示内容 |
| 难度评分 | 任务后 1–7 分，1 非常难、7 非常容易 |
| 推荐理解 | 能否说出至少两个来自自己回答的推荐依据 |
| 预算理解 | 正确 / 部分正确 / 错误 |

任务后追问（每任务）：

- 你刚才认为下一步会发生什么？
- 哪个词或按钮让你犹豫？
- 如果没有主持人在旁边，你会继续、退出还是换一种方式？

小样本不追求统计显著性。时间与评分只用于发现异常，原话、行为路径和重复卡点优先。

## 7. 结束访谈脚本（逐字照读，不超过 5 分钟）

1. 你觉得这个产品最主要在帮你做什么？
2. 哪一步最让你犹豫？为什么？
3. 推荐理由是否足以让你相信这个结果与回答有关？
4. "更多推荐"让选择更容易还是更困难？
5. 你认为预算和商家价格是什么关系？
6. 如果下次再用，你最希望系统记住什么？

最后再说明：原型中 AI、登录、位置和商家均为模拟，不让该信息提前影响任务表现。

## 8. 通过门槛与严重度判定速查

### 首轮通过门槛（全部满足才可完成 P0-06）

- T1、T2、T4 的独立完成率均不低于 80%；
- 没有参与者在不必要时被迫进入 AI；
- 至少 80% 的参与者能说出两个真实推荐依据；
- 所有参与者都理解预算不保证商家价格；
- 至少 1 人完成纯键盘主路径；
- 没有 S0/S1 未关闭问题；
- S2 问题有明确修订方案并完成必要复测；
- 结果、时间、干预、卡点和参与者原话均已落入记录。

若参与者只有 3 人，80% 门槛按 3/3 处理；4 人按 4/4；5 人按 4/5。

### 严重度判定

| 等级 | 定义 | 处理 |
|---|---|---|
| S0 阻断 | 无法继续、数据丢失、无恢复路径 | 立即修复并完整复测 |
| S1 严重 | 关键任务失败、价格/隐私/登录边界被误解 | 进入 P0-07 前必须修复并复测 |
| S2 中等 | 能完成但明显犹豫、误操作或需干预 | 本轮修订或形成明确接受理由 |
| S3 轻微 | 文案、视觉或效率问题 | 进入设计债务清单 |

**同一问题被 2 名及以上参与者独立遇到，严重度至少上调一档**，除非有明确证据说明两次来源不同。

## 9. 会话后收尾与归档

每个参与者结束后：

- [ ] 完成该参与者记录文件的"测试后总结"（最顺畅/最困难步骤、是否愿再使用、未决点、建议纳入汇总的问题）
- [ ] 为每条问题分配 ID（`U01-01` 等）和严重度 S0–S3
- [ ] 纯键盘参与者补齐"纯键盘附加记录"表
- [ ] 检查是否遗漏卡点原话；遗漏则立即补记

全部参与者结束后，汇总产物（交付给 Claude 进行分析）：

- 3–5 份匿名单人记录（`P0-06_U01~U05_观察记录.md`）；
- 每份文件的完成情况（可另附汇总表：任务完成率、中位时间、卡点、原话、严重度）；
- 至少一条真人纯键盘整链证据；
- 需要修订的页面与文案清单（问题 ID + 建议）。

汇总后由 Claude 生成正式汇总报告、修订原型、复测并更新实施计划与项目记忆。
