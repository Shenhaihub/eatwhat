> 文档状态：权威术语基线  
> 生效日期：2026-07-23  
> 上游文档：`01_EatWhat_PRD_产品需求文档_v1.2_权威需求基线.md`  
> 用途：统一 PRD、流程、原型、数据库、API、AI、测试和代码中的含义。

---

# 1. 使用规则

1. 同一个概念只使用一个首选名称和一个稳定代码。
2. 展示文案可以调整，稳定代码不能随文案变化。
3. 下游文档需要新增术语时，先在本文件定义，再使用。
4. “用户说法”“UI 文案”和“后端代码”含义不同时，必须分别标明。
5. 客户端不能自行决定来源、用户身份、额度消费或可信状态。

# 2. 产品与流程术语

| 首选术语 | 英文/代码参考 | 定义 | 不应混用 |
|---|---|---|---|
| 推荐流程 | recommendation flow | 从预设问卷开始，经 AI 追问和最终候选，到用户选定食物的流程 | 不包含附近商家查询本身 |
| 附近商家流程 | nearby merchant flow | 用户已有明确食物/品牌目标后，选择地点并查询 POI 的流程 | 不称为 AI 推荐 |
| 直接选择路径 | direct selection path | 用户从社区、活动或明确食物候选直接进入附近商家 | 不经过 AI、不消耗 AI 额度 |
| 主任务 | primary task | 用户完成食物决定并进入附近商家/地图 | 不包括评价、调查和分享 |
| 非强制收尾 | optional completion branch | 主任务后可选的评价、调查、匿名分享 | 不得成为完成条件 |
| 食物类型 | food category | 可用于推荐和 POI 搜索的稳定饮食类别 | 不等于具体商家或菜品实例 |
| 食物代码 | `food_code` | 食物类型的稳定机器代码 | 不使用展示中文作为主键 |
| 明确食物选择 | explicit food selection | 用户已选定一个 food_code，可以直接找附近商家 | 不再进入 AI 推荐 |
| 候选食物 | candidate food | 规则或 AI 认为可供选择的 food_code | 不等于用户最终选择 |
| 首个候选 | primary recommendation | priority=1、初始唯一展示的候选 | 不宣称绝对最佳 |
| 更多推荐 | more recommendations | 用户主动展开剩余候选的操作 | 固定按 1→3→5 展示 |

# 3. 问卷术语

| 首选术语 | 英文/代码参考 | 定义 |
|---|---|---|
| 问卷版本 | `questionnaire_version` | 决定问题库、条件表和解释方式的版本 |
| 七个信息维度 | seven questionnaire dimensions | 用餐时段、食量/状态、一般忌口、口味、预算、最大距离、明确食物倾向 |
| 基础预设题 | base predefined questions | 推荐开始时稳定展示的 2–3 个问题，用于获得基础高信息量信号 |
| 自适应预设题 | adaptive predefined questions | 后端规则根据已有答案从题库选择的后续 2–3 个问题 |
| 预设题库 | predefined question bank | 由项目维护、版本化、可测试的问题和选项集合 |
| 条件表 | condition table | 描述问题何时可选、跳过、提高优先级或互斥的声明式规则 |
| 问卷决策引擎 | Questionnaire Decision Engine | 根据版本和完整答案确定下一题、覆盖维度和失效答案的后端确定性规则能力 |
| 问卷决策图 | decision graph / DAG | 问题依赖和分支关系；允许不同路径重新汇合，不要求是严格树结构 |
| 完整答案快照 | `answers_so_far` | 当前所有仍有效的结构化问卷答案，不只是最后一次提交 |
| 失效答案 | `invalidated_answer_ids` | 因用户修改早期回答而不再属于当前有效路径的后续答案 |
| 问卷完成 | questionnaire complete | 七个维度达到规则定义的完成条件，可以进入 AI 登录边界 |
| AI 追问 | AI follow-up question | AI 基于预设问卷和之前 AI 回答逐轮生成的单个问题 |

## 3.1 七个信息维度代码

| 维度 | 建议代码 | 说明 |
|---|---|---|
| 用餐时段 | `meal_period` | 早餐、午餐、下午茶、晚餐、夜宵等 |
| 食量/状态 | `appetite` | 当前想吃多少、偏轻或偏丰盛等 |
| 一般忌口 | `avoidances` | 日常排除项，不构成过敏/医疗保证 |
| 口味 | `tastes` | 辣、清淡、咸香等倾向 |
| 单人用餐预算 | `budget` | 本次一人正餐预计实付的软偏好，仅用于食物方向推荐；不保证具体商户实际消费 |
| 最大距离 | `max_distance_m` | 用户愿意接受的搜索半径偏好 |
| 明确食物倾向 | `explicit_food_preference` | 是否已有可直接选择的 food_code |

## 3.2 预算档位与价格术语

| 术语 | 建议代码 | 定义 |
|---|---|---|
| 20 元以下 | `under_20` | 单人预计实付 `< 20` 元 |
| 20–30 元 | `from_20_to_30` | 单人预计实付 `20–30` 元，包含边界 |
| 30 元以上 | `over_30` | 单人预计实付 `> 30` 元；界面辅助文案为“今天想吃好一点” |
| 食物预算适配 | `food_budget_fit` | 根据版本化食物词典判断某类食物是否通常有机会落在该预算档；属于软匹配 |
| 商家参考价格 | `merchant_reference_price` | 仅在 POI/合法数据源明确返回且附带来源时可展示的参考值，不是最终实付承诺 |
| 商家预算符合 | 不设默认代码 | 第一阶段不做该业务断言；没有可靠价格数据时不得生成或展示 |

预算默认指单人堂食/到店消费预期，不含配送费、平台补贴、随机优惠、多人分摊和临时加购。若以后支持外卖或多人场景，必须另设上下文，不得复用当前档位并假装语义相同。

# 4. AI 术语

| 首选术语 | 英文/代码参考 | 定义 |
|---|---|---|
| AI 推荐会话 | recommendation session | 登录后承载 AI 追问、最终生成、额度和历史的一次业务会话 |
| 追问轮次 | follow-up round | 一次“生成一个 AI 问题 → 用户回答”的循环 |
| 最大追问轮次 | `max_follow_up_rounds=3` | 服务端硬上限，不允许 AI 自行突破 |
| 提前结束 | early stop | 信息充分时在未达到 3 轮前结束追问并进入最终生成 |
| 最终生成 | final generation | AI 基于全部有效上下文固定生成 5 个食物候选 |
| 结构化输出 | structured output | 必须通过服务端 schema 校验的 AI 响应 |
| 规则回退 | rule fallback | AI 不可用或输出非法时，由规则返回非空候选 |
| 用户推荐额度 | user recommendation quota | 用户每天可成功完成的 AI 推荐会话次数，当前为 3 次 |
| 模型调用预算 | provider call budget | 一次会话允许的内部模型调用上限：最多 3 次追问 + 1 次最终生成 |
| 尝试限流 | attempt rate limit | 防止用户反复创建/放弃会话消耗 Provider API 的独立限制 |
| AI 等待状态 | AI wait state | 下一题或最终生成期间的前端可见反馈状态 |

# 5. 地点与商家术语

| 首选术语 | 英文/代码参考 | 定义 |
|---|---|---|
| 地点上下文 | LocationContext | 当前一次商家搜索使用的短期地点信息 |
| 浏览器定位 | browser geolocation | 用户主动授权得到的本次位置，通常为 WGS84 |
| 手动地点 | manual location | 用户搜索地点/商圈后得到的位置 |
| 演示地点 | demo location | Mock、拒绝定位或演示使用的预设地点 |
| POI Provider | POIProvider | 查询和归一化第三方商户数据的后端抽象 |
| 附近商家 | nearby merchants | 对已选食物/品牌目标执行一次 POI 搜索得到的商户列表 |
| 最近匹配 | nearest match | 依据距离和搜索相关性得到的结果描述 | 
| 地图入口 | map action | 打开地图服务查看最新详情/导航的操作 |

“附近商家”不得称为“AI 推荐商家”；“最近匹配”不得称为“最好吃”。

# 6. 首页、社区与活动术语

| 首选术语 | 英文/代码参考 | 定义 |
|---|---|---|
| 社区模块 | community foods | “今天大家都在吃什么”及其冷启动状态 |
| 真实匿名聚合 | anonymous aggregate | 达到样本阈值、无法回链账户的食物选择统计 |
| 默认食物建议 | default food suggestions | 冷启动使用的配置内容，不显示虚构人数 |
| 真实人数 | real count | 达到隐私阈值后可以展示的真实匿名记录数量 |
| 活动 | activity | 有来源、有效期、核验时间和搜索目标的配置内容 |
| 活动搜索目标 | activity search target | 明确 food_code 或经过配置的 brand_keyword/POI 关键词 |

默认食物建议不得称为“真实热门排行”；Mock 内容不得混入 Live 统计。

# 7. 反馈、调查与分享术语

| 首选术语 | 英文/代码参考 | 定义 |
|---|---|---|
| 快速评价 | feedback | 与登录用户/推荐会话关联的简短产品反馈 |
| 改进问卷 | improvement survey | 用户主动展开的可选详细反馈，不进入公共统计 |
| 匿名分享 | anonymous share | 用户单独同意后创建、与账户和推荐会话无直接回链的最小公共记录 |
| 分享预览 | share preview | 分享前展示将公开字段的确认界面 |
| 匿名撤回凭据 | anonymous revocation credential | 可选的不关联账户的撤回凭据；是否进入首版待下游决定 |

匿名分享不得包含问卷答案、AI 追问、口味、忌口、预算、距离、精确位置、商家、邮箱、用户 ID 或推荐会话 ID。

# 8. 来源类型

来源由服务端根据真实执行路径派生。

| 代码 | 定义 | AI 额度 |
|---|---|---:|
| `ai_recommended` | 用户从 AI 的 5 个最终候选中选择 | 成功后消耗 1 次完整推荐额度 |
| `user_selected` | 用户在明确食物入口/问卷候选中直接选择 | 不消耗 |
| `community_selected` | 用户从社区模块选择 | 不消耗 |
| `activity_selected` | 用户从活动入口选择 | 不消耗 |

客户端不得在创建/更新请求中自行声明可信来源；可以传入口意图，最终 source_type 由后端决定。

# 9. 推荐业务状态

以下是业务语义基线，API/数据库可以细化命名，但不得改变含义。

| 业务状态 | 建议代码 | 含义 |
|---|---|---|
| 问卷进行中 | `questionnaire_in_progress` | 正在完成基础/自适应预设题 |
| 等待登录 | `awaiting_login` | 问卷完成，下一步将调用 AI，但用户未登录 |
| AI 追问生成中 | `ai_follow_up_generating` | 正在生成一个下一问题 |
| 等待追问回答 | `ai_follow_up_ready` | 下一问题已返回，等待用户回答 |
| 最终生成中 | `final_generating` | 正在生成固定 5 个候选 |
| 推荐成功 | `succeeded` | 5 个候选已通过校验 |
| 已选食物 | `food_selected` | 用户已经选择一个 food_code |
| 商家已展示 | `merchants_shown` | 已完成一次附近商家查询 |
| 已完成 | `completed` | 主任务完成，可进入非强制收尾 |
| 失败 | `failed` | 当前步骤失败且需要重试/回退 |
| 已取消 | `cancelled` | 用户主动结束会话 |

问卷决策引擎本身可以无服务端持久会话；上述 AI 推荐业务状态从登录后创建 recommendation_session 起生效。

# 11. 模式术语

| 术语 | 定义 |
|---|---|
| Mock 模式 | 不使用真实 AI/POI secrets，可重复模拟正常、慢、错误、超时和空结果 |
| Live 模式 | 使用真实认证、AI 和地图 Provider |
| 规则模式 | 不调用 AI，由规则产生问卷路径或最终候选 |
| 降级 | 外部能力失败后切换到可完成的规则/替代路径 |

Mock/Live 是整体来源语义，不能把单条 Mock 商户混进 Live 结果并冒充真实。

# 12. 容易混淆的表达

| 不推荐表达 | 推荐表达 | 原因 |
|---|---|---|
| AI 选餐厅 | AI 推荐食物类型 | 商户事实由 POI Provider 提供 |
| 固定七步问卷 | 七维混合自适应问卷 | 七个维度不等于七个页面 |
| AI 一次问 3 题 | AI 逐轮追问，最多 3 轮 | 下一题必须能使用上一题回答 |
| 返回 3–5 个 | 固定返回 5 个，按 1→3→5 展示 | 避免数量/UI 状态不一致 |
| 匿名但保留 user_id | 去标识或删除回链字段 | 保留直接关联就不是真正不可回链 |
| 大家都在吃（无数据） | 没想法？看看这些 | 不制造虚假群体背书 |
| 最好吃的店 | 最近匹配/相关商家 | 系统没有可靠口味质量数据 |
| 符合预算的商家 | 附近相关商家；实际价格以门店为准 | 首版没有稳定、完整的商家价格数据 |
| 预算匹配 | 食物方向适合该预算档 | 避免把食物层软匹配误解为商家价格保证 |
| AI 正在深度思考 | 正在生成下一题/准备推荐结果 | 不伪装或泄露模型内部思维过程 |
